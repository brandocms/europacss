# Releases and preview builds

The repository contains two implementations: the experimental native compiler and the legacy JavaScript/PostCSS package. Their versions and build commands are separate.

## Native npm beta

The first native npm release is being prepared as **0.1.0-beta.0**. Package
preparation does not mean the version is published. Check the public registry
before handing installation commands to consumers.

The CLI, adapter, Cargo executable and all platform packages share one version:

- `@brandocms/europacss-cli` exposes `europa` and `getBinaryPath()`.
- `@brandocms/vite-plugin-europacss` depends on that exact CLI version.
- `@brandocms/europacss-<platform>` contains the matching executable and notices.

`packages/cli/platforms.json` defines seven targets: macOS arm64/x64, Linux
arm64/x64 with glibc or musl, and Windows x64. The GNU build runners use Ubuntu
22.04; consumer validation runs in `node:22` and `node:24`. Alpine binaries are
built and tested with musl. Every platform is tested with both Node 22 and 24,
both npm and pnpm 10.32.1, and Vite 6.4.3 and 8.3.0. Windows arm64 is not yet
supported. Binaries are unsigned and not notarized.

The CLI's optional platform dependencies are generated by the packer, keeping
source-workspace development possible before the first registry publication.
There are no install scripts or external executable downloads. Do not publish
`packages/cli` directly: it lacks the generated optional-dependency map.

### Build and test locally

```sh
cargo fmt --all -- --check
cargo clippy --locked -p europacss --all-targets -- -D warnings
cargo test --locked -p europacss
npm ci --prefix packages --ignore-scripts
npm test --prefix packages
python3 scripts/package-rust.py
```

The last command writes an archive and checksum under `dist/native/`. It extracts
and smoke-tests the native executable with an empty PATH. Dependency notices and
source URLs are included; missing notices fail packaging. Versioned supplements
for incomplete upstream crate archives live under `scripts/licenses/`.

Use the archive path printed by that command:

```sh
python3 scripts/package-npm.py --shared --archive dist/native/europa-0.1.0-beta.0-aarch64-apple-darwin.tar.gz
node scripts/test-npm.mjs --manager npm
node scripts/test-npm.mjs --manager pnpm
```

The pnpm test expects a global pnpm 10.32.1 installation, or `EUROPA_PNPM_CLI`
pointing to a local `pnpm.cjs`. Run these tests with both Node 22 and 24.
They serve the packed tarballs through a read-only local registry, install in a
fresh directory with scripts disabled, reinstall from the lockfile, and check
CLI compilation, migration, failing exit status and Vite builds. An adapter-only
install verifies that compiler resolution does not depend on a direct CLI
installation or a PATH lookup. Ordinary dependencies come from npm.

### CI and publication

[Native npm packages](.github/workflows/native-release.yml) runs for relevant
branch pushes, pull requests and manual dispatches. These runs build and test
artifacts without publishing. It also runs the complete native/compiler and
adapter checks from [rust.yml](.github/workflows/rust.yml).

1. Set the same version in Cargo and the CLI/adapter manifests, including the
   adapter's exact compiler dependency. Refresh Cargo.lock and the `packages/`
   npm workspace lockfile. The packer rejects inconsistent versions.
2. Let all platform builds, Node 22/24 consumer tests and compiler/adapter checks
   pass on the release commit. Review the `npm-*` and `archive-*` artifacts.
3. Configure npm publishing access to the `@brandocms` scope. For the first
   publication of new package names, publish the **tested tarballs** from an
   authenticated npm session (with any required 2FA).
4. Before the next release, configure each package's trusted publisher for
   `brandocms/europacss`, workflow `native-release.yml`, environment `npm`, with
   direct `npm publish` allowed. Use the GitHub `npm` environment for the
   publishing job. Trusted publishing requires npm >=11.5.1 and Node >=22.14;
   the release job uses Node 24. With npm >=11.15.0, the configuration command is:

   ```sh
   npm trust github @brandocms/europacss-cli --repo brandocms/europacss --file native-release.yml --env npm --allow-publish --yes
   ```

   Repeat for the adapter and all seven platform packages. This requires an
   authenticated package maintainer with account 2FA. A new configuration must
   complete its first successful publish within two days or it expires, so
   configure it when that next release is ready. See [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/).
5. For later releases, push the matching `native-v0.1.0-beta.N` tag. Only those
   tags run the publisher, after all checks pass. Branch/manual runs never
   publish. The JavaScript workflow excludes native tags.

Download all nine `npm-*` package tarballs and their checksums into one directory.
The publisher defaults to validation only:

```sh
node scripts/publish-npm.mjs --packages dist/npm
# First publication, after registry authentication and successful CI:
node scripts/publish-npm.mjs --packages dist/npm --publish
```

CI adds `--provenance` and uses npm OIDC trusted publishing. All packages publish
with public access under `beta`; the JavaScript package's `latest` tag is
unchanged. Platform packages publish first, then CLI, then adapter. The script
checks the complete set, exact versions, manifests and checksums before writes.
It skips an already-published version only when its registry integrity matches
the tested tarball, so a partial publication can be resumed. A changed tarball
requires a new version. Do not rebuild artifacts between validation and publish.

After publication, validate actual registry installs on Node 22 and Node 24:

```sh
node scripts/test-npm.mjs --registry https://registry.npmjs.org --version 0.1.0-beta.0 --manager npm
node scripts/test-npm.mjs --registry https://registry.npmjs.org --version 0.1.0-beta.0 --manager pnpm
```

### Brando handoff

Pin both public packages to the same exact beta version in generated apps and
the E2E consumer. Remove Europa-specific Yalc/PATH setup. Keep `.yalc` copies
still needed by `@brandocms/brandojs`. Move Brando's build/CI images to Node 24
as part of that consumer change, keeping the pinned pnpm version consistent.
Run clean installs, generated-app and E2E builds, Docker builds and Brando's CI
release gates. Compare compiled admin CSS with round 5; packaging should not
change CSS output. EuropaCSS's own support matrix continues to cover Node 22.

## HTML documentation

```sh
cd docs
yarn install --frozen-lockfile
yarn build
```

VitePress writes `docs/.vitepress/dist`, served under `/europacss/`. The [Pages workflow](.github/workflows/docs.yml) deploys relevant pushes to `master` or explicit workflow runs. Building locally does not deploy.

## Legacy JavaScript package

The root `package.json` identifies the PostCSS package. Its existing release process updates `CHANGELOG.md` and the root version, runs `yarn test` and `yarn build`, then commits the release. Historical tags use the version without a `v` prefix.

The [npm workflow](.github/workflows/npmpublish.yml) publishes the root package for numeric version tags; `native-v*` tags are excluded. Creating/pushing a release tag is a publication action; it is separate from local commits and native preview builds. Do not also run a duplicate manual publish for a release handled by that workflow.
