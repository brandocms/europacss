# Cascade and layers

By default, Europa emits common rules before responsive rules. A responsive token overrides
its fallback at matching widths even when the fallback is written last:

```css
.title {
  @fontsize xl $lg;
  font-size: 24px;
}
```

With `xl` set to `48px` at a desktop breakpoint of `1024px`, this behaves like:

```css
.title { font-size: 24px; }
@media (width >= 1024px) {
  .title { font-size: 48px; }
}
```

Media queries do not increase selector specificity. They follow common rules in
the output, so they win when the other cascade priorities tie. Higher-specificity
selectors and `!important` retain their normal CSS behavior.

## Responsive ordering

With `responsiveOrder: 'all-last'` (the default), this applies to authored `@media`, `@responsive` / `@mq`, and media generated by
directives such as `@fontsize` and `@space`. It also applies across selector rules
and bundled local imports in one compilation:

```css
.title { @fontsize xl $lg; }
.compact { font-size: 24px; }
```

An element matching both classes uses the responsive `xl` value on large screens.
Use a later layer when an application override should win at every viewport.

Media queries keep their authored relative order. Europa does not globally sort
overlapping width ranges, print, orientation, or preference queries. Breakpoints
generated by one directive follow numeric breakpoint order. The optimizer can
compact equivalent queries when that preserves their results.

Common declarations keep their source order: `@color fg red; color: blue;` still
produces blue. Nesting semantics are chosen separately with the
[`nesting` option](./nesting#expanded-selector-mode).
Ordering is per compilation, not across independent stylesheet links or separate
Vite CSS modules. Layers can establish precedence across those entries.

### Keep authored media in place

Set `responsiveOrder: 'generated-last'` in the JSON5 config to preserve authored
`@media` at its source position. Nested authored media expands at its parent's
position. Europa directive media still follows the common/authored rules in its
scope, in the same relative order as before:

```css
/* Source */
@media (width < 600px) { .compact { padding: 8px; } }
.title { @responsive $desktop { padding: 24px; } }
.override { padding: 12px; }

/* With generated-last */
@media (width < 600px) { .compact { padding: 8px; } }
.override { padding: 12px; }
/* The expanded $desktop query containing .title follows here. */
```

An element matching `.compact.override` therefore keeps `12px` at narrow widths.
The generated `.title` rule still wins on an element also matching `.override`
when its breakpoint matches. The same rules apply to media produced by spacing,
font-size, column, unpack, and other Europa directives.

`@responsive` counts as generated media, matching its append behavior in 0.13.
`@mq` was not available in 0.13; its current alias follows `@responsive`.
Authored media copied through placeholders remains authored. The optimizer may
combine equivalent rules where that preserves the cascade.

This option inherits through `extends`. It changes media ordering only; it does
not reproduce all 0.x behavior or remove the boundaries below.

## Conditions and registration boundaries

Responsive rules stay inside their enclosing `@layer`, `@supports`, `@container`,
`@scope`, and `@starting-style` blocks. Nested media queries retain all their
conditions. Europa orders each group's contents independently.
Repeated blocks of the same named layer are separate ordering boundaries; media
does not move between them.

Layer declarations, imports, and unknown at-rules are ordering barriers. Media
cannot move across them. A conditional or selector containing a layer boundary
is also a barrier in its enclosing scope. `@font-face`, `@property`, `@keyframes`,
and prefixed keyframes are transparent to media reordering: registrations keep
their relative order while responsive style rules can follow later common rules.
Conditions around registrations are retained.

The native compiler retains an authored leading layer-order statement at the
front of the output, including names whose layers are empty. A later bundler or
minifier can still shorten that statement while preserving its order.

### Migrating a package with many CSS files

Legacy 0.x directive media could be appended after the whole processed sheet.
To retain that package-wide scope, import **one aggregate file** with a layer:

```css
/* entry.css */
@layer reset, vendor, brando, app;
@import './brando.css' layer(brando);
```

```css
/* brando.css */
@import './BlockEditor.css';
@import './FieldBase.css';
```

Inside `brando.css`, use ordinary unlayered component imports. Applying
`layer(brando)` separately to every component creates separate ordering
boundaries, even though all declarations belong to the same CSS layer. Earlier
responsive styles can then lose to later common rules. Migration analysis flags
potential equal-specificity conflicts across those blocks; verify the old and
new builds with [browser comparison](../guide/compare). Keep genuinely distinct
layers and conditions separate.

Under the default `'all-last'`, authored `@media` also moves after common rules. Different equal-specificity
selectors can therefore change which declaration wins on elements matching both.
The analyzer reports potential conflicts; DOM overlap requires browser evidence.
For 0.x migrations, use `'generated-last'` alongside the aggregate import to
retain authored media order while appending directive media across the package.
The analyzer compares the selected ordering mode; it does not report authored
media as moved when it stayed in place. Other order checks still apply.

## A layer convention for Brando

Declare the complete order before loading vendor, Brando, or application styles:

```css
@layer reset, vendor, brando, app;

@layer brando {
  #brando-main .button {
    @fontsize xl $lg;
    font-size: 24px;
  }
}

@layer app {
  .button { font-size: 18px; }
}
```

For normal declarations, later layers take precedence before selector specificity
is compared. The application gets `18px` at all widths without matching Brando's
selector specificity. Brando's media rules remain inside `brando`.

Europa bundles can use a normal layer block:

```css
@layer reset {
  @europa base;
}
```

Existing local files can be assigned a layer at import time:

```css
@layer reset, vendor, brando, app;
@import './reset.css' layer(reset);
@import './vendor.css' layer(vendor);
@import './brando.css' layer(brando);
@import './app-overrides.css' layer(app);
```

These are exact local paths. The Rust resolver also resolves CSS packages through `node_modules`; the Vite adapter supplies aliases and its host-specific resolution. Avoid wrapping an already layered stylesheet a second
time unless nested layers are intended.

This is an integration convention, not automatic compiler wrapping. Brando's
package, vendor styles, consumer entry points, and overrides need to adopt it
together. In Vite, load the layer-order stylesheet before other CSS imports so
production extraction and development injection share the same order.

Unlayered normal styles outrank all named layers. `!important` reverses layer
precedence: earlier layers beat later layers and unlayered important declarations.
Europa preserves these [standard CSS rules](https://www.w3.org/TR/css-cascade-5/#layer-order).

## Runtime themes

An optional theme layer can sit between Brando and the application:

```css
@layer reset, vendor, brando, theme, app;

@layer theme {
  :root { --brando-accent: #3563e9; }
  [data-admin-theme="warm"] { --brando-accent: #b34b31; }
}
```

CSS custom properties support runtime branding; JSON5 tokens supply values at
build time. Layer precedence compares declarations on the same element. A custom
property set directly on an element still beats an inherited ancestor value.

## Upgrading a native preview

Earlier native previews preserved media/common source order. A later common
declaration could override a preceding responsive token; it now acts as the
fallback. Compare affected components at their breakpoints when updating.

Legacy PostCSS migrations no longer need to reorder simple responsive/fallback
pairs. Other differences remain: non-media declaration appending, overlapping
query sorting, native selector specificity, and breakpoint boundaries. Migration
reports use analyzer version 14; regenerate older saved reviews.
